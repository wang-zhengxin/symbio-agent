# Symbio Agent · 多智能体协作工作台

[English](README.en.md)

Symbio Agent 是独立实现的本机多 Agent 与真人协作工作台。通过 Codex、Pi 执行任务，统一管理成员、小队、Skills、MCP、项目资料和 Token 预算。看板、列表、表格与 3D 数字办公室共享 SQLite 中的任务和执行事件，并通过 SSE 实时更新。

## 启动

首次部署、后台运行、远程采集、升级及备份恢复见 [部署手册](docs/DEPLOYMENT.md)。

需要 Node.js 22.13 或更高版本。安装 Apogee 首页依赖并启动：

```sh
npm install
npm start
```

打开 [Apogee 首页](http://127.0.0.1:4317/) 或直接进入 [本机工作台](http://127.0.0.1:4317/office)。首次打开工作台时创建首位管理员。首次启动同时创建产品研发组、交付记录技能和五个员工档案。

首位管理员和后续成员均需通过邮件验证码注册。后续成员在登录页选择「注册账号」，管理员在「设置 → 工作区管理 → 账号与权限」审批，并可调整角色或停用账户。已有账户继续使用用户名和密码登录，尚未绑定邮箱的账户在进入工作台前需要完成邮箱验证。

用户可在「设置 → 通知」开启或关闭 @ 邮件通知，默认关闭。发评论时可选择是否向已开启通知的 @ 用户发送邮件。邮件包含评论正文和任务入口，工作台收件箱仍会收到 @ 通知。

在项目根目录的 `.env` 或服务进程环境中配置 SMTP，然后运行 `npm start`。请使用邮件服务商授权的发件邮箱和 SMTP 凭据。

```dotenv
OFFICE_SMTP_HOST=smtp.example.com
OFFICE_SMTP_PORT=587
OFFICE_SMTP_FROM=workspace@example.com
OFFICE_SMTP_USER=workspace@example.com
OFFICE_SMTP_PASS="你的 SMTP 授权码"
```

默认使用 587 端口并要求 STARTTLS。465 端口使用 TLS，也可通过 `OFFICE_SMTP_SECURE=1` 为其他端口启用直接 TLS。允许免登录的 SMTP 中继可同时省略用户名和密码。验证码有效期为 10 分钟，每个邮箱发送间隔为 60 秒，服务重启后需重新获取。

首页源码位于 `apogee/`，`npm run dev` 启动首页的 Vite 预览。使用 `npm start` 可以同时验证首页和工作台的跳转。Suisse 字体由 [OnlineWebFonts](https://www.onlinewebfonts.com/fonts) 提供。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `OFFICE_PORT` | `4317` | 本机 HTTP 端口 |
| `OFFICE_DATA_DIR` | 项目中的 `data/` | 数据库与执行目录 |
| `OFFICE_CONCURRENCY` | 使用「运行时」设置，初始为 `3` | 指定后覆盖工作台的并发上限 |
| `OFFICE_CODEX_BIN` | `codex` | Codex CLI 路径 |
| `OFFICE_PI_BIN` | `pi` | Pi CLI 路径 |
| `OFFICE_PI_PROVIDER_EXTENSION` | 未设置 | 可选，指定一个信任的 Pi 模型提供商扩展入口的绝对路径 |
| `OFFICE_COLLECTOR_PORT` | 工作台端口加一（默认 `4318`） | 独立采集入口，设为 `0` 可关闭 |
| `OFFICE_COLLECTOR_HOST` | `127.0.0.1` | 采集入口的监听地址 |

服务监听 IPv4 回环地址。同一数据目录使用一个服务实例。

## Symbio 工作空间

侧栏按使用场景组织，导航名称、页面标题和面包屑保持一致。下表为管理员可见入口，普通成员仅显示其有权限访问的页面。

| 分组 | 入口 | 用途 |
| --- | --- | --- |
| 快捷入口 | 搜索、新建任务、收件箱、我的任务、聊天 | 查找工作内容、处理通知和查看协作会话 |
| 工作 | 任务、项目、定时任务 | 执行与验收任务，查看项目进度和一次性定时派发 |
| AI 团队 | 智能体、小队、Skills、运行时、发现与入职 | 配置能力、组织团队、管理执行环境及审批候选 |
| 数字办公室 | 办公室、空间与工位 | 查看实时 3D 工作状态，编辑布局并管理席位 |
| 底部入口 | 统计、设置、帮助中心 | 查看 Token 用量与预算，管理工作区和个人设置 |

右上角账号按钮展开轻量菜单，可直接进入个人资料、账号与权限或设置。点击外部或按 Esc 收起，方向键可选择菜单项。

### 任务视图

- 「任务」支持看板、列表和表格三种视图，浏览器会记住所选视图。列表可按状态折叠；表格支持状态分组、列显隐、标题或编号搜索，以及全部筛选结果或勾选任务的 CSV 导出。
- 「我的任务」仅显示分配给当前账号关联真人成员的顶层任务；「定时任务」显示设置了派发时间的任务，目前支持一次性派发。
- 子任务不直接出现在任务面板，可在父任务详情中查看。各视图共用任务筛选、详情、评论及状态操作。
- 从任务页或项目页的团队看板进入「大屏模式」，可查看全屏 3D 办公室、拖拽切换视角。点击角色查看状态和相关任务，详情在右侧展开；退出大屏返回原页面。

### 数字办公室与项目


- 「数字办公室 → 办公室」用 WebGL 展示轴测办公空间。创建或编辑真人、Agent 和候选入职档案时，可选择 8 套人物形象并预览动作。每个角色独立随机安排休息：连续空闲 30–60 分钟后寻找空置休息点，可在休息区就座，5–10 分钟后返回工位。任务和会话优先。两人对谈面对面就座，第三人加入后转入会议室。点击角色或名单可查看状态和相关任务。可切换至平面视图查看已发布的自定义布局。
- 前台角色固定在接待位；当前管理员对应的真人老板固定在独立办公室。
- 「空间与工位 → 工位管理」展示同一份 3D 工位和员工分配。新员工优先使用空置工位，满员时自动在办公室右侧扩建。管理员可批量增加空置工位，两个页面会同步更新。

- 项目页展示项目进度、团队日历和当日安排。项目可以填写负责人和截止日期，任务可以同时关联真人与 Agent。真人负责的任务可以手动推进和提交验收。
- 「设置 → 工作区管理 → 成员」可以编辑真人档案、筛选并导出名单。真人的在线标记由档案维护。智能体页面可查看配置、运行记录、用量和待处理审批。暂停派发会保留排队任务，正在执行的任务继续完成。
- 空间与工位可编辑区域位置、席位、团队分配和显示组件。保存草稿供后续编辑，发布后办公室使用已发布的配置。

## 工作区设置

设置采用「主导航 → 设置分类 → 内容」三栏布局。窄屏下分类自动换行，内容保持可滚动。

| 分类 | 页面 |
| --- | --- |
| 个人设置 | 个人资料、偏好设置、通知 |
| 工作区管理 | 常规、成员、账号与权限 |
| 任务配置 | 任务状态、标签、属性 |
| 连接与扩展 | MCP |
| 系统记录 | 操作记录 |

成员档案管理真人与 Agent 的身份、岗位和团队归属；账号与权限管理能够登录工作台的真实用户。Skills、小队和运行时拥有独立侧栏入口。

- 「常规」管理工作区名称、简介、操作者和任务编号。Codex 和 Pi 使用执行入队时的工作区上下文，任务历史保留编号。
- 「任务状态」可调整看板阶段的显示名称和默认优先级。「标签」与「属性」用于任务分类，字段支持文本、数字和单选。归档会保留现有任务值。
- 「运行时」管理本机并发、执行时限、默认 Token 预留和本机扫描策略。「小队」管理团队；「统计」查看用量并管理预算；「Skills」管理技能，「设置 → 连接与扩展 → MCP」管理工具接入。
- 「通知」管理个人 @ 邮件通知；管理员还可以配置工作区收件箱的事件类型。收件箱可统一标记已读，「操作记录」显示最近的管理操作。
- 「偏好设置」在当前浏览器保存外观、任务默认视图和显示时区。任务页可搜索编号或内容，也可按项目、负责人、优先级和标签筛选。打开任务详情可查看执行历史和发表评论。

## 自动发现与入职

打开「发现与入职」。工作台默认在启动时扫描本机，之后每 10 秒扫描一次。可在「运行时」修改间隔或改用手动扫描。扫描识别 PATH 和常用安装目录中的 CLI，以及采集账号能看到的相关进程。当前识别 Codex、Pi、Claude Code、Gemini CLI、OpenCode、Aider、Cursor Agent、Copilot CLI、Qwen Code、Kiro CLI 和 OpenClaw。安装项可以长期绑定员工，进程项按本次启动单独识别。

候选默认处于「待建档」。可人工填写档案，或点击「交给人事」，创建并启动一条人事任务来拟定档案。档案包含姓名、人格、职责、岗位、小队、技能和执行权限。管理员核对「待确认」档案并批准后，候选才成为正式员工。

已在运行的进程和远程来源采用「仅采集」，人格和技能保存在公司档案中。本机 Codex 和 Pi 安装项可在入职时选择平台执行，派任务时会启动新会话。采集只上报主机名、系统、安装清单和进程标识，进程存在表示运行器可见。任务、对话、命令参数和 Token 用量沿用各自的执行数据通道。

## 从另一台机器采集

采集器已发布到 npm，当前版本为 `symbio-agent-collector@0.1.0`。目标机器安装 Node.js 22.13 或更高版本后，可以直接运行后台生成的配对命令。 [npm 包](https://www.npmjs.com/package/symbio-agent-collector/v/0.1.0)

1. 让目标机器能访问采集端。若采集端使用默认的本机监听，在目标机器先建立 SSH 隧道，并保持该终端开启。把 `user@office-host` 换成工作台主机的 SSH 用户名和地址。

   ```sh
   ssh -N -L 4318:127.0.0.1:4318 user@office-host
   ```

2. 在工作台「发现与入职 → 配对新机器」填写机器名称和接收地址，选择「macOS / Linux」或「Windows PowerShell」。使用上述 SSH 隧道时，填写 `http://127.0.0.1:4318`。
3. 点击「生成启动命令」，复制「首次启动」，在目标机器的另一个终端执行。命令包含这台机器专用的配对密钥，并通过 `npx` 下载指定版本。完成配对后，采集器会立即上报并持续运行。在「采集机器」看到该机器显示「在线」即接入成功。

采集器将配对保存在 `~/.agent-office/collector.json`。在同一机器、同一系统账号下，使用后台的「配对后重新启动」命令即可恢复采集。每台机器独立配对，可在工作台撤销。 [远程采集部署与排障](docs/DEPLOYMENT.md#5-接入远程采集机器)

直接接入可在工作台主机把 `OFFICE_COLLECTOR_HOST` 设为局域网 IP 或 `0.0.0.0`，用 `OFFICE_COLLECTOR_TLS_CERT` 和 `OFFICE_COLLECTOR_TLS_KEY` 指定可信证书与密钥，再在配对时填写 `https://主机名:4318`。可通过 `OFFICE_COLLECTOR_PUBLIC_URL` 预填可达地址。可信局域网的 HTTP 联调需要工作台设置 `OFFICE_COLLECTOR_ALLOW_HTTP=1`，后台会为生成的命令添加 `--allow-http`。

客户端在 macOS、Linux 使用进程表，Windows 使用 PowerShell CIM。运行采集的账号和环境决定可见进程范围。macOS 已做端到端验证。

## 跑一遍任务

1. 在「AI 团队 → 智能体」选择或创建 Agent。Codex 需要已登录且支持 App Server 的 CLI。Pi 需要支持 JSON 事件模式的 CLI，并在终端运行 `pi` 后用 `/login` 登录模型提供商，或配置可用的本地模型。模型留空时沿用相应运行器的本机配置。
2. 如需先验证流程，把一个员工的运行器设为「演示运行器」。演示事件有明确标记，演示不会访问模型或产生真实 Token 用量。
3. 在「工作 → 任务」创建任务，填写负责人、验收标准和可选的前置任务。启动后打开「执行详情」，可看计划、工具活动、输出、产出路径及运行器报错。
4. 成功执行进入「待验收」。验收后，依赖它的任务才允许启动。失败任务可以重试，旧执行记录会保留。

每次执行使用独立目录 `data/workspaces/<执行 ID>`，页面显示目录和新产生的文件路径。只读与执行目录可写模式由 Codex 沙箱执行。当前两种模式用于约束文件写入，职责说明和技能文本用于指导行为。人事、财务和会议发言均使用只读模式。

Pi 执行任务和讨论，接收公司档案中的人格、职责和技能。Pi 的内置文件与命令工具、公司管理工具及扩展自动加载保持关闭。若现有登录依赖一个模型提供商扩展，在启动工作台时用 `OFFICE_PI_PROVIDER_EXTENSION` 指定该入口文件，并在员工档案中填写对应的模型 ID（如 `provider/model`）。Pi 使用当前用户的登录配置。扩展以工作台账号运行，扩展入口由启动工作台的人指定。需要调用人事或财务管理工具的任务分配给对应岗位的 Codex 员工。

## Skills 与 MCP

1. 在「AI 团队 → Skills」点击「下载技能」，选择来源后浏览或搜索，点击「下载」直接加入技能库。支持 [Anthropic Skills](https://github.com/anthropics/skills)、[OpenAI Plugins](https://github.com/openai/plugins)、[Vercel Agent Skills](https://github.com/vercel-labs/agent-skills)、[skills.sh](https://skills.sh) 和 [SkillsMP](https://skillsmp.com)。后两个目录需要输入关键词。也可以上传 `SKILL.md` 或粘贴正文进行手动导入。下载后在员工档案中勾选技能。任务入队时保存当时的技能正文，执行详情中的提示词可查看该版本。
2. 在「设置 → 连接与扩展 → MCP」添加 MCP 服务。填写 Streamable HTTP 地址（HTTPS 或回环地址上的 HTTP）或本机 stdio 命令（绝对路径和 JSON 参数数组），逐项填写允许的工具名。HTTP Bearer 鉴权支持 `OFFICE_MCP_*` 环境变量，将变量值设在工作台服务环境中，页面只登记变量名。stdio 服务以工作台账号启动，应选用信任的程序。
3. 在 Codex 或 Pi 员工档案中选择允许使用的服务。Pi 需支持 `builtin:mcp`（已用 1.5.1 验证）。MCP 授权用于平台派发的任务，生效时检查员工当前绑定和服务启用状态。停用后影响后续启动的任务，正在执行的任务如需立即停止可在执行详情中中止。工具开始、完成和失败出现在执行时间线。

目录下载会固定 Git 提交版本，保存技能正文及该目录中的脚本、引用等配套文件；重复下载同一仓库、同一路径会复用现有技能，不覆盖本地修改。技能卡片可查看来源及版本。文件保存在 `OFFICE_DATA_DIR/skill-packages/`，备份和迁移时须与 SQLite 数据库一并保留。单个技能目录限 256 个文件、16 MB，单文件限 4 MB，正文限 32,000 字符；失败时清理未完成的下载。

执行时将分配的技能复制到任务目录的 `.office-skills/<skill-id>/`。Codex 可按技能说明读取配套文件；Pi 当前接收技能正文，内置文件及 Shell 工具仍被禁用，配套脚本需要运行器具备相应工具。下载本身不执行脚本。手动导入只保存 Markdown 正文。

公开来源无需填写 API Key，服务端需要能够访问 GitHub API、raw.githubusercontent.com 和对应目录站点。来源限流或网络失败会在页面显示错误并提供重试；不支持私有仓库。skills.sh 当前每次最多返回 50 条结果，可以用更具体的关键词缩小范围。

## 项目公共工作区

- 从项目列表打开「公共工作区」，上传共享文件，预览文本，或下载任意历史版本。上传到已有路径会生成新版本。项目设置可以登记 HTTPS Git 仓库链接，方便从工作台跳转。
- 派单时固定项目资料和已验收的前置任务交付。Codex 在执行目录的 `.office-inputs/project/` 和 `.office-inputs/dependencies/` 读取副本。需要归档的文件写入 `deliverables/`，其中的相对路径即共享路径。Pi 通过提示词接收版本清单和小型文本摘录，文本结果可进入验收。
- 「待发布」显示本次交付，可对比开工基线、当前版本和草稿。验收后整批发布。任何同名文件的基线过期都会阻止整批发布，审核人可退回重跑，或确认将交付发布为新版本。
- 文件内容存放在 `OFFICE_DATA_DIR/project-space/`，版本元数据在同一数据目录的 SQLite 数据库中。单文件上限为 16 MiB，项目当前版本合计最多 100 个文件、128 MiB。

## 项目任务与讨论

- 在新建任务时可设置一次「定时派发」并选择 Agent 负责人。到时自动进入现有调度队列。前置任务未验收或负责人暂停时，系统会等到条件满足再派发。项目列表可直接打开该项目的主任务看板。
- 在任务详情的「子任务」中查看和添加拆分工作。Codex 项目负责人也可以在执行时创建并派发子任务。子任务沿用父任务的项目，在详情中单独执行与验收。父任务需等所有子任务验收或取消后才能验收。
- 「任务讨论」支持发帖、回复以及 @ 成员。@ 真人会进入本机收件箱，@ Agent 会排队生成同线程回复，使用该 Agent 的预算。正在执行的 Codex 可随时读取和发表评论。Pi 在任务输出结束时提交单独的评论，收到 @ 后也可以异步回复。

## 人事、财务与协作

- 把创建员工的任务交给「人事」，例如“招聘一名测试工程师，加入产品研发组”。人事通过公司工具创建普通员工，新员工默认只读。管理页面也可以直接配置岗位、人格、职责、技能、小队和运行器。
- 把汇总用量的任务交给「财务」。财务可查询账本，在公司额度内调整小组或其他员工的额度。公司总预算由页面设置。账本依据运行器实际上报的 Token，以执行为单位记录。预算是累计内部额度，不是供应商的账户余额。启动前预留，执行中按上报扣减，结束释放剩余预留。上报是分批到达的，预留额度用于准入控制。
- 在「聊天」选择至少两名员工并发起讨论。两人是双人交流，加入第三人后切换为会议室模式。参与者轮流发言，每个发言独立入队并计量。可从讨论创建关联后续任务。结束讨论时，系统取消排队发言或停止当前发言。
- 同一员工一次处理一个执行，不同员工在并发上限内同时运行。服务意外退出后的运行中记录会标记为中断，待执行任务重新调度。

## 数据流和验证

```text
HTTP 操作 → SQLite 事务（业务状态与事件）
        → 调度队列 → 本机运行器
        → 统一执行事件 → SQLite → SSE → 浏览器视图
```

首次打开时浏览器读取状态快照，再按游标订阅 SSE。重连时服务补发遗漏事件，运行详情提供最近 300 条事件。Codex 使用 App Server 的 stdio 接口和动态工具能力，Pi 使用 JSON 事件流。两种运行器的输出与用量使用相同的任务和财务记录。[Codex App Server](https://learn.chatgpt.com/docs/app-server) · [Pi JSON 事件流](https://pi.dev/docs/latest/json)

从任务的「执行详情」可查看工作台注入的指令、任务或会话输入、阶段计时与工具调用耗时。计时来自工作台收到的事件，首段输出指第一段可见文本。新执行保存入队时的指令；历史指令按入队配置还原，耗时按已有事件拆分。
