# Agent 公司 · 本机工作台

独立实现的本机 Agent 管理应用。任务看板、组织、财务和协作页面共享 SQLite 中的任务、执行记录与事件。会话已保存双人交流和多人会议两种模式，可供后续 3D 视图消费。

## 启动

首次部署、后台运行、远程采集、升级及备份恢复见 [部署手册](docs/DEPLOYMENT.md)。

需要 Node.js 22.13 或更高版本。安装 Apogee 首页依赖并启动：

```sh
npm install
npm start
```

打开 [Apogee 首页](http://127.0.0.1:4317/) 或直接进入 [本机工作台](http://127.0.0.1:4317/office)。首次打开工作台时创建首位管理员。首次启动同时创建产品研发组、交付记录技能和五个员工档案。

首位管理员和后续成员均需通过邮件验证码注册。后续成员在登录页选择「注册账号」，管理员在「设置 → 用户管理」审批，并可调整角色或停用账户。已有账户继续使用用户名和密码登录，尚未绑定邮箱的账户在进入工作台前需要完成邮箱验证。

用户可在「设置 → 我的账户」开启或关闭 @ 邮件通知，默认关闭。发评论时可选择是否向已开启通知的 @ 用户发送邮件。邮件包含评论正文和任务入口，工作台收件箱仍会收到 @ 通知。

在项目根目录的 `.env` 或服务进程环境中配置 SMTP，然后运行 `npm start`。请使用邮件服务商授权的发件邮箱和 SMTP 凭据。

```dotenv
OFFICE_SMTP_HOST=smtp.example.com
OFFICE_SMTP_PORT=587
OFFICE_SMTP_FROM=workspace@example.com
OFFICE_SMTP_USER=workspace@example.com
OFFICE_SMTP_PASS="你的 SMTP 授权码"
```

默认使用 587 端口并要求 STARTTLS。465 端口使用 TLS，也可通过 `OFFICE_SMTP_SECURE=1` 为其他端口启用直接 TLS。允许免登录的 SMTP 中继可同时省略用户名和密码。验证码有效期为 10 分钟，每个邮箱发送间隔为 60 秒，服务重启后需重新获取。

首页源码位于 `apogee/`，`npm run dev` 启动首页的 Vite 预览。使用 `npm start` 可以同时验证首页和工作台的跳转。Suisse 字体由 [OnlineWebFonts](https://www.onlinewebfonts.com/fonts) 提供。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `OFFICE_PORT` | `4317` | 本机 HTTP 端口 |
| `OFFICE_DATA_DIR` | 项目中的 `data/` | 数据库与执行目录 |
| `OFFICE_CONCURRENCY` | 使用「运行与采集」设置，初始为 `3` | 指定后覆盖工作台的并发上限 |
| `OFFICE_CODEX_BIN` | `codex` | Codex CLI 路径 |
| `OFFICE_PI_BIN` | `pi` | Pi CLI 路径 |
| `OFFICE_PI_PROVIDER_EXTENSION` | 未设置 | 可选，指定一个信任的 Pi 模型提供商扩展入口的绝对路径 |
| `OFFICE_COLLECTOR_PORT` | 工作台端口加一（默认 `4318`） | 独立采集入口，设为 `0` 可关闭 |
| `OFFICE_COLLECTOR_HOST` | `127.0.0.1` | 采集入口的监听地址 |

服务监听 IPv4 回环地址。同一数据目录使用一个服务实例。

## Symbio 工作空间

侧栏提供实时监控、项目工作台、员工管理、Agent 管理和布局管理。顶部搜索可查找项目、任务及员工，收件箱通过通知铃铛打开。设置、财务、发现与入职和协作会话使用同一套布局。

- 「实时监控 → 数字办公室」用 WebGL 展示轴测办公空间。创建或编辑真人、Agent 和候选入职档案时，可选择 8 套人物形象并预览动作。角色连续空闲 30–60 分钟后会寻找空置的休息点，休息 5–10 分钟后返回工位。任务和会话优先。两人对谈面对面就座，第三人加入后转入会议室。点击角色或名单可查看状态和相关任务。可切换至平面视图查看已发布的自定义布局。
- 「布局管理 → 工位管理」展示同一份 3D 工位和员工分配。新员工优先使用空置工位，满员时自动在办公室右侧扩建。管理员可批量增加空置工位，两个页面会同步更新。

- 项目工作台展示项目进度、团队日历和当日安排。项目可以填写负责人和截止日期，任务可以同时关联真人与 Agent。真人负责的任务可以手动推进和提交验收。
- 员工目录可以编辑真人档案、筛选并导出名单。真人的在线标记由档案维护。Agent 管理可查看配置、运行记录、用量和待处理审批。暂停派发会保留排队任务，正在执行的任务继续完成。
- 布局管理可编辑区域位置、席位、团队分配和显示组件。保存草稿供后续编辑，发布后实时监控使用已发布的配置。

## 工作区设置

- 「基本资料」管理工作区名称、简介、操作者和任务编号。Codex 和 Pi 使用执行入队时的工作区上下文，任务历史保留编号。
- 「任务流程」可调整看板阶段的显示名称和默认优先级。「标签」与「自定义字段」用于任务分类，字段支持文本、数字和单选。归档会保留现有任务值。
- 「运行与采集」管理本机并发、执行时限、默认 Token 预留和本机扫描策略。「组织与预算」提供员工、技能、小组和账本的入口。
- 「通知」决定收件箱展示待验收、执行失败、待入职和机器离线中的哪些事件。可统一标记已读，「变更记录」显示最近的管理操作。
- 「偏好」在当前浏览器保存外观、任务默认视图和显示时区。任务页可搜索编号或内容，也可按项目、负责人、优先级和标签筛选。打开任务详情可查看执行历史和发表评论。

## 自动发现与入职

打开「发现与入职」。工作台默认在启动时扫描本机，之后每 10 秒扫描一次。可在「运行与采集」修改间隔或改用手动扫描。扫描识别 PATH 和常用安装目录中的 CLI，以及采集账号能看到的相关进程。当前识别 Codex、Pi、Claude Code、Gemini CLI、OpenCode、Aider、Cursor Agent、Copilot CLI、Qwen Code、Kiro CLI 和 OpenClaw。安装项可以长期绑定员工，进程项按本次启动单独识别。

候选默认处于「待建档」。可人工填写档案，或点击「交给人事」，创建并启动一条人事任务来拟定档案。档案包含姓名、人格、职责、岗位、小组、技能和执行权限。管理员核对「待确认」档案并批准后，候选才成为正式员工。

已在运行的进程和远程来源采用「仅采集」，人格和技能保存在公司档案中。本机 Codex 和 Pi 安装项可在入职时选择平台执行，派任务时会启动新会话。采集只上报主机名、系统、安装清单和进程标识，进程存在表示运行器可见。任务、对话、命令参数和 Token 用量沿用各自的执行数据通道。

## 从另一台机器采集

1. 在工作台「发现与入职 → 采集机器」下载 `office-collector.mjs`，复制到目标机器。目标机器需安装 Node.js 22.13 或以上版本。
2. 在工作台点击「配对新机器」，命名并保存当次显示的配对密钥。每台机器使用独立密钥。
3. 让目标机器能访问采集端口。默认可在目标机器开 SSH 转发，`office-host` 换成工作台所在机器，端口与实际设置一致：

   ```sh
   ssh -N -L 4318:127.0.0.1:4318 user@office-host
   ```

4. 在目标机器另一个终端执行以下命令，安装时粘贴密钥：

   ```sh
   node office-collector.mjs install http://127.0.0.1:4318
   node office-collector.mjs run
   ```

   `install` 会立即验证配对并保存配置到 `~/.agent-office/collector.json`，`run` 持续上报。用 `run --once` 可以检查一次连接。客户端退出后约 40 秒，机器会标为离线。可在工作台撤销密钥，重新配对前移走客户端旧配置。

如果不用 SSH 转发，可以在工作台主机把 `OFFICE_COLLECTOR_HOST` 设为局域网 IP 或 `0.0.0.0`，并用 `OFFICE_COLLECTOR_TLS_CERT` 和 `OFFICE_COLLECTOR_TLS_KEY` 指定可信的证书与密钥，再用 `https://主机名:4318` 安装。可信局域网的 HTTP 联调需要工作台设置 `OFFICE_COLLECTOR_ALLOW_HTTP=1`，客户端安装命令加 `--allow-http`。采集端口只接收 `POST /v1/report`，管理页面仍绑定本机。

客户端在 macOS、Linux 使用进程表，Windows 使用 PowerShell CIM。运行采集的账号和环境决定可见进程范围。macOS 已做端到端验证。

## 跑一遍任务

1. 在「组织与员工」选择或创建员工。Codex 需要已登录且支持 App Server 的 CLI。Pi 需要支持 JSON 事件模式的 CLI，并在终端运行 `pi` 后用 `/login` 登录模型提供商，或配置可用的本地模型。模型留空时沿用相应运行器的本机配置。
2. 如需先验证流程，把一个员工的运行器设为「演示运行器」。演示事件有明确标记，演示不会访问模型或产生真实 Token 用量。
3. 在「任务看板」创建任务，填写负责人、验收标准和可选的前置任务。启动后打开「执行详情」，可看计划、工具活动、输出、产出路径及运行器报错。
4. 成功执行进入「待验收」。验收后，依赖它的任务才允许启动。失败任务可以重试，旧执行记录会保留。

每次执行使用独立目录 `data/workspaces/<执行 ID>`，页面显示目录和新产生的文件路径。只读与执行目录可写模式由 Codex 沙箱执行。当前两种模式用于约束文件写入，职责说明和技能文本用于指导行为。人事、财务和会议发言均使用只读模式。

Pi 执行文本任务和讨论，接收公司档案中的人格、职责和技能说明。运行时关闭文件与命令工具、公司管理工具、MCP 和扩展自动加载。若现有登录依赖一个模型提供商扩展，在启动工作台时用 `OFFICE_PI_PROVIDER_EXTENSION` 指定该入口文件，并在员工档案中填写对应的模型 ID（如 `provider/model`）。Pi 使用当前用户的登录配置。扩展以工作台账号运行，扩展入口由启动工作台的人指定。需要调用人事或财务管理工具的任务分配给对应岗位的 Codex 员工。

## 项目公共工作区

- 从项目列表打开「公共工作区」，上传共享文件，预览文本，或下载任意历史版本。上传到已有路径会生成新版本。项目设置可以登记 HTTPS Git 仓库链接，方便从工作台跳转。
- 派单时固定项目资料和已验收的前置任务交付。Codex 在执行目录的 `.office-inputs/project/` 和 `.office-inputs/dependencies/` 读取副本。需要归档的文件写入 `deliverables/`，其中的相对路径即共享路径。Pi 通过提示词接收版本清单和小型文本摘录，文本结果可进入验收。
- 「待发布」显示本次交付，可对比开工基线、当前版本和草稿。验收后整批发布。任何同名文件的基线过期都会阻止整批发布，审核人可退回重跑，或确认将交付发布为新版本。
- 文件内容存放在 `OFFICE_DATA_DIR/project-space/`，版本元数据在同一数据目录的 SQLite 数据库中。单文件上限为 16 MiB，项目当前版本合计最多 100 个文件、128 MiB。

## 项目任务与讨论

- 在新建任务时可设置一次「定时派发」并选择 Agent 负责人。到时自动进入现有调度队列。前置任务未验收或负责人暂停时，系统会等到条件满足再派发。项目列表可直接打开该项目的主任务看板。
- 在任务详情的「子任务」中查看和添加拆分工作。Codex 项目负责人也可以在执行时创建并派发子任务。子任务沿用父任务的项目，在详情中单独执行与验收。父任务需等所有子任务验收或取消后才能验收。
- 「任务讨论」支持发帖、回复以及 @ 成员。@ 真人会进入本机收件箱，@ Agent 会排队生成同线程回复，使用该 Agent 的预算。正在执行的 Codex 可随时读取和发表评论。Pi 在任务输出结束时提交单独的评论，收到 @ 后也可以异步回复。

## 人事、财务与协作

- 把创建员工的任务交给「人事」，例如“招聘一名测试工程师，加入产品研发组”。人事通过公司工具创建普通员工，新员工默认只读。管理页面也可以直接配置岗位、人格、职责、技能、小组和运行器。
- 把汇总用量的任务交给「财务」。财务可查询账本，在公司额度内调整小组或其他员工的额度。公司总预算由页面设置。账本依据运行器实际上报的 Token，以执行为单位记录。预算是累计内部额度，不是供应商的账户余额。启动前预留，执行中按上报扣减，结束释放剩余预留。上报是分批到达的，预留额度用于准入控制。
- 在「协作会话」选择至少两名员工并发起讨论。两人是双人交流，加入第三人后切换为会议室模式。参与者轮流发言，每个发言独立入队并计量。可从讨论创建关联后续任务。结束讨论时，系统取消排队发言或停止当前发言。
- 同一员工一次处理一个执行，不同员工在并发上限内同时运行。服务意外退出后的运行中记录会标记为中断，待执行任务重新调度。

## 数据流和验证

```text
HTTP 操作 → SQLite 事务（业务状态与事件）
        → 调度队列 → 本机运行器
        → 统一执行事件 → SQLite → SSE → 浏览器视图
```

首次打开时浏览器读取状态快照，再按游标订阅 SSE。重连时服务补发遗漏事件，运行详情提供最近 300 条事件。Codex 使用 App Server 的 stdio 接口和动态工具能力，Pi 使用 JSON 事件流。两种运行器的输出与用量使用相同的任务和财务记录。[Codex App Server](https://learn.chatgpt.com/docs/app-server) · [Pi JSON 事件流](https://pi.dev/docs/latest/json)

从任务的「执行详情」可查看工作台注入的指令、任务或会话输入、阶段计时与工具调用耗时。计时来自工作台收到的事件，首段输出指第一段可见文本。新执行保存入队时的指令；历史指令按入队配置还原，耗时按已有事件拆分。

```sh
npm test
```

测试覆盖事务回滚、Token 并发预留和重复上报、会议升级与取消、岗位工具权限、Codex 协议回放，以及采集进程识别、机器授权和入职审批。
